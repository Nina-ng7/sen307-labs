# Lab 4 Notes: DML and Referential Integrity

In Part 4, I created the department "Library and Information Science", added a student to it, and then tried to delete the department. MySQL returned Error 1451: "Cannot delete or update a parent row: a foreign key constraint fails." MySQL refuses because the Student table has a foreign key (dept_id) pointing to that department, and deleting it would leave the student pointing to a department that no longer exists. This is how referential integrity protects the data. I fixed it by first running an UPDATE to move the student to the Software Engineering department, after which the DELETE succeeded and the student was kept rather than lost. Another way to fix it would be to define the foreign key with ON DELETE CASCADE, which automatically deletes the dependent students along with the department, or ON DELETE SET NULL, which keeps the students but clears their dept_id (this only works if dept_id allows NULL). I could also have deleted the dependent student first, then the department.
